# 虎丘婚纱城多端库存订单系统（需求清单+详细设计+数据库设计）

> 版本：V1.0 文档类型：PRD需求清单 + 系统详细设计说明书 + 数据库设计说明书 业务范围：商家、仓库、婚纱衣服库存、销售人员、销售订单、改衣订单、报表 客户端：商家PC管理端、销售开单端（PC+微信小程序）

------

## 第一部分 需求清单（PRD）

### 1 项目概述

#### 1.1 项目背景

虎丘婚纱城商户需要一套多端系统管理自有婚纱礼服业务，包含仓库、商品SKU库存、销售人员账号、销售订单、改衣订单、经营报表；分为商家管理员后台、销售员开单端，实现库存自动锁定、释放，单据状态跟踪，数据权限隔离。

#### 1.2 角色与端说明

1. 商家端（PC网页，管理员角色）
    - 添加、查询仓库、衣服SKU、库存；
    - 维护销售人员账号信息；
    - 查询全部销售订单、改衣订单；
    - 首页经营数据报表、库存预警；
    - 全量增删改查权限。
2. 销售端（PC网页+微信小程序，销售员角色）
    - 创建销售订单、改衣订单；
    - 修改本人单据状态；
    - 仅查看自己创建的单据；
    - 无商品维护、无全店报表、无法查看其他销售员单据。

#### 1.3 核心业务规则

1. 单据分为：销售订单（售卖 / 租赁）、改衣订单（必须绑定销售订单）；
2. 库存字段：总库存、可用库存、占用库存；
3. 开单取货锁定库存；订单取消、客户归还自动释放库存；
4. 改衣接单时商品临时锁定，不能被其他订单选中；改衣完工/取消后解除锁定；
5. 数据隔离：销售员仅能查看本人创建单据，商户之间数据隔离。

#### 1.4 需求优先级

- P0（一期必上）：账号登录权限、仓库&商品库存管理、销售员管理、销售单/改衣单新建、状态流转、库存自动变更、单据打印、基础查询；
- P1（二期迭代）：首页经营报表、Excel批量导入导出、库存盘点、销售员业绩统计；
- P2（三期优化）：客户档案、收款记账、扫码开单、消息提醒（待归还、待改衣预警推送）。

### 2 功能需求 FR

#### 2.1 账号与权限模块（P0）

FR001 登录校验：账号密码登录，区分管理员、销售员；JWT会话，超时自动登出；密码加密存储。 FR002 权限控制：

- 商家管理员：全部菜单、全部数据的增删改查；
- 销售员：仅销售开单、改衣开单、本人订单查询，隐藏库存维护、人员管理、报表；
- 支持销售员账号启用/禁用，离职账号冻结。

#### 2.2 商家端功能

##### （1）仓库管理

FR003 多仓库维护：新增、编辑、删除仓库，支持主仓、试衣间临时仓等，单商户多仓库独立核算库存。

##### （2）婚纱商品SKU库存管理

FR004 商品档案维护：款号、商品名称、分类、尺码、颜色、进价、售价、租赁价、商品图片；支持新增、编辑、下架、删除，Excel批量导入商品。 FR005 库存管理：总库存、可用库存、占用库存；支持手动入库、出库、盘点；库存变动自动写入流水日志。 FR006 库存查询：支持款号、名称、分类、仓库、库存状态筛选，库存清单导出Excel。

##### （3）销售人员管理

FR007 人员维护：新增销售员（姓名、手机号、登录账号、密码），编辑信息、启用/禁用，姓名检索人员列表。

##### （4）销售订单管理

FR008 订单查询：查看本店全部销售员订单；筛选条件：时间段、销售员、订单状态、客户姓名、款号。 FR009 订单基础信息：订单号、开单人、客户姓名、客户电话、租售类型、商品明细、金额、下单时间、订单状态。 FR010 订单状态流转：草稿 → 已开单 → 已取货 → 已归还 → 已完成 → 已取消。 FR011 订单操作：查看详情、导出Excel、打印单据、作废异常订单。

##### （5）改衣订单管理

FR012 改衣订单必须绑定销售订单，自动带出客户、商品信息。 FR013 改衣单字段：改衣单号、关联销售单号、修改项目、改衣费用、预计完工时间、单据状态。 FR014 改衣单状态：待接单 → 修改中 → 已完工 → 已交付 → 已取消。 FR015 管理员查看全店改衣单，支持筛选、导出。

##### （6）首页经营报表（P1）

FR016 数据看板：今日/本周/本月订单数量、成交总额；销售员业绩排行；租赁、售卖订单占比；待取货、待归还、待改衣数量预警。 FR017 库存统计：占用库存统计、滞销款式统计；图表+表格展示，报表导出。

#### 2.3 销售端开单功能（P0）

##### （1）销售订单开单

FR018 新建销售订单：录入客户信息；选择仓库+商品SKU，自动带出价格；选择租赁/售卖类型；自动生成单号；支持保存草稿、提交开单；提交成功自动扣减可用库存、增加占用库存。 FR019 订单状态修改：仅可修改本人订单；状态流转：已开单→已取货→已归还→已完成；未取货订单取消自动释放库存。 FR020 个人订单查询：只查看本人单据，筛选、查看详情、打印单据。

##### （2）改衣订单开单

FR021 新建改衣订单：选择已生效销售订单，自动带出商品和客户信息；填写改衣项目、改衣费用、预计完工时间；生成改衣单号，锁定商品库存。 FR022 改衣单状态维护：待接单→修改中→已完工→已交付；取消改衣单解除商品锁定。 FR023 仅可查询本人创建的改衣单据。

#### 2.4 非功能需求 NFR

1. 单据打印：销售订单、改衣订单支持小票打印；
2. 单号规则：年月日+流水号，全局唯一；
3. 并发控制：多销售员同时开单，防超卖，库存使用乐观锁；
4. 操作日志：库存变动、订单修改记录操作人、操作时间；
5. 兼容性：商家端适配Chrome浏览器；销售端支持PC网页+微信小程序；
6. 导出：库存、订单列表支持Excel导出；系统定时数据备份；
7. 性能：页面加载≤2s，开单保存响应≤1s。

### 3 业务流程

1. 管理员创建仓库、录入婚纱SKU、新增销售员账号；
2. 销售员登录销售端，新建销售订单，锁定婚纱库存；
3. 同一份销售订单可绑定多条改衣订单，商品临时锁定；
4. 取货、归还、改衣完工后，销售员更新单据状态，系统自动释放库存；
5. 商家管理员后台统一查看全部订单、库存流水、经营报表。

## 第二部分 系统详细设计说明书

### 1 总体设计

#### 1.1 系统架构（前后端分离）

- 前端
    - 商家管理端：Vue3 + Element Plus（PC网页）
    - 销售开单端：Vue3 + Vant（PC网页 + 微信小程序）
- 后端：SpringBoot + MyBatis-Plus + JWT权限控制
- 数据库：MySQL 8.0
- 接口规范：RESTful JSON
- 数据隔离：所有业务数据携带商户ID，行级权限隔离，商户之间数据不可互通。

#### 1.2 模块划分

1. 权限模块：登录认证、角色管理、账号启停；
2. 基础资料模块：仓库管理、商品SKU、销售员管理；
3. 库存模块：库存维护、库存流水、库存锁定与释放；
4. 订单模块：销售订单（主单+明细）、改衣订单（主单）；
5. 打印模块：单据PDF/小票打印；
6. 报表模块：经营统计、库存统计（仅商家端访问）。

#### 1.3 角色权限矩阵

| 角色       | 可见菜单                     | 允许操作                                                     |
| ---------- | ---------------------------- | ------------------------------------------------------------ |
| 商家管理员 | 全部菜单                     | 新增、编辑、删除、查询全部数据，查看报表、导出所有单据       |
| 销售员     | 销售开单、改衣开单、我的订单 | 创建本人订单、修改本人单据状态；仅查询自己单据；无法维护库存、看不到报表 |

### 2 核心业务流程详细设计

#### 2.1 销售订单下单、库存扣减流程

1. 销售员提交销售订单；
2. 后端开启数据库事务；
3. 校验商品可用库存 ≥ 下单数量；
4. 使用乐观锁version锁定库存行；
5. 可用库存 -= 数量；占用库存 += 数量；
6. 写入销售订单主表、明细表；
7. 写入库存变动流水日志；
8. 事务提交；库存不足、版本冲突直接抛出异常，事务回滚。

#### 2.2 订单归还/取消，库存释放流程

1. 更新销售订单状态为【已归还/已取消】；
2. 开启事务；
3. 可用库存 += 数量；占用库存 -= 数量；
4. 写入库存流水；
5. 事务提交。

#### 2.3 改衣订单库存锁定逻辑

改衣订单接单成功后，商品标记为改衣占用，其他销售开单无法选中该商品；改衣单完工、取消时，解除锁定，恢复可用库存。

### 4 前端页面规划

#### 商家端页面

1. 首页：数据看板、预警卡片、图表；
2. 基础资料：仓库管理、商品SKU管理、销售员管理；
3. 库存管理：库存列表、库存流水、库存盘点；
4. 订单管理：销售订单列表、改衣订单列表；
5. 系统设置：个人密码修改。

#### 销售端页面

1. 首页：新建销售单、新建改衣单快捷入口；
2. 我的订单：销售订单列表、改衣订单列表；
3. 单据详情、单据打印；
4. 个人密码修改。

### 5 异常与并发处理方案

1. 超卖控制：inventory库存表增加version乐观锁，更新库存必须携带版本号；版本不一致拒绝更新；
2. 事务边界：订单创建+库存变更放在同一个事务，原子操作；
3. 单号防重复：Redis生成每日自增流水号拼接日期生成业务单号；
4. 越权拦截：接口统一校验，销售员查询单据强制过滤 create_user_id = 当前登录用户id；
5. 列表统一分页，默认每页20条；
6. 商品图片上传对象存储，数据库只存图片URL；
7. 大数据导出异步化，后台生成文件后供前端下载。

### 6 非功能设计要点

- 操作日志入库，记录操作人、IP、操作内容；
- 接口统一返回码规范，统一异常捕获；
- 文件上传限制大小、格式校验；
- 会话token设置过期时间。

## 第三部分 数据库设计说明书（MySQL8.0）

### 1 设计原则

1. 遵从第三范式，减少冗余；
2. 所有业务表携带 merchant_id，实现商户数据隔离；
3. 主键 bigint 自增；业务单据号为字符串唯一键；
4. 库存表增加乐观锁 version，解决并发超卖；
5. 通用字段：create_time、update_time。

### 2 ER关系简述

- 商户(1) — 用户(N)：一个商户多个管理员、销售员；
- 商户(1) — 仓库(N)：一个商户多个仓库；
- 仓库(1) — 库存(N)：仓库下多个商品库存记录；
- 用户(1) — 销售订单(N)：销售员可以开多张销售单；
- 销售订单(1) — 销售订单明细(N)；
- 销售订单(1) — 改衣订单(N)：一笔销售单可多条改衣单；
- 商品(1) — 库存流水(N)：每一次库存变动生成流水记录。

### 3 建表SQL

```
-- 商户表 merchant
CREATE TABLE `merchant` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '商户ID',
  `merchant_name` VARCHAR(100) NOT NULL COMMENT '商户名称',
  `contact_phone` VARCHAR(20) COMMENT '联系电话',
  `address` VARCHAR(200) COMMENT '门店地址',
  `status` TINYINT DEFAULT 1 COMMENT '状态 1正常 0停用',
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商户信息表';

-- 系统用户表 sys_user（管理员+销售员）
CREATE TABLE `sys_user` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `merchant_id` BIGINT NOT NULL COMMENT '所属商户ID',
  `username` VARCHAR(30) NOT NULL UNIQUE COMMENT '登录账号',
  `password` VARCHAR(100) NOT NULL COMMENT '加密密码',
  `real_name` VARCHAR(30) NOT NULL COMMENT '姓名',
  `phone` VARCHAR(20) COMMENT '手机号',
  `role` TINYINT NOT NULL COMMENT '角色：1商家管理员 2销售员',
  `status` TINYINT DEFAULT 1 COMMENT '1启用 0禁用',
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_merchant (merchant_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='系统用户';

-- 仓库表 warehouse
CREATE TABLE `warehouse` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `merchant_id` BIGINT NOT NULL COMMENT '商户ID',
  `warehouse_name` VARCHAR(50) NOT NULL COMMENT '仓库名称',
  `remark` VARCHAR(200) COMMENT '备注',
  `status` TINYINT DEFAULT 1,
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_merchant (merchant_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='仓库';

-- 商品分类表 goods_category
CREATE TABLE `goods_category` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `merchant_id` BIGINT NOT NULL,
  `category_name` VARCHAR(50) NOT NULL COMMENT '分类：婚纱/秀禾/礼服/西装',
  `sort` INT DEFAULT 0,
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_merchant (merchant_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品分类';

-- 商品主表 goods（婚纱SKU）
CREATE TABLE `goods` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `merchant_id` BIGINT NOT NULL,
  `sku_code` VARCHAR(50) NOT NULL UNIQUE COMMENT '唯一款号',
  `goods_name` VARCHAR(100) NOT NULL COMMENT '商品名称',
  `category_id` BIGINT NOT NULL COMMENT '分类ID',
  `size` VARCHAR(30) COMMENT '尺码',
  `color` VARCHAR(30) COMMENT '颜色',
  `purchase_price` DECIMAL(10,2) COMMENT '进价',
  `sale_price` DECIMAL(10,2) COMMENT '售卖价',
  `rent_price` DECIMAL(10,2) COMMENT '租赁价',
  `goods_img` VARCHAR(255) COMMENT '图片URL',
  `status` TINYINT DEFAULT 1 COMMENT '1正常 0下架',
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_merchant (merchant_id),
  INDEX idx_sku (sku_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='婚纱商品SKU';

-- 库存表 inventory（核心，分仓库库存）
CREATE TABLE `inventory` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `merchant_id` BIGINT NOT NULL,
  `warehouse_id` BIGINT NOT NULL COMMENT '仓库ID',
  `goods_id` BIGINT NOT NULL COMMENT '商品ID',
  `total_stock` INT NOT NULL DEFAULT 0 COMMENT '总库存',
  `available_stock` INT NOT NULL DEFAULT 0 COMMENT '可用库存',
  `occupy_stock` INT NOT NULL DEFAULT 0 COMMENT '占用库存（订单+改衣锁定）',
  `version` INT NOT NULL DEFAULT 1 COMMENT '乐观锁版本号',
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_warehouse_goods (warehouse_id,goods_id),
  INDEX idx_merchant (merchant_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='仓库库存';

-- 库存流水日志 inventory_log
CREATE TABLE `inventory_log` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `merchant_id` BIGINT NOT NULL,
  `warehouse_id` BIGINT NOT NULL,
  `goods_id` BIGINT NOT NULL,
  `change_type` TINYINT NOT NULL COMMENT '1入库 2出库 3订单占用 4订单释放 5盘点调整',
  `change_num` INT NOT NULL COMMENT '变动数量，正数增加，负数减少',
  `order_no` VARCHAR(50) COMMENT '关联订单号',
  `oper_user_id` BIGINT NOT NULL COMMENT '操作人',
  `remark` VARCHAR(200),
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_merchant (merchant_id),
  INDEX idx_goods (goods_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='库存变动日志';

-- 销售订单主表 sale_order
CREATE TABLE `sale_order` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `merchant_id` BIGINT NOT NULL,
  `order_no` VARCHAR(50) NOT NULL UNIQUE COMMENT '销售单号',
  `sale_user_id` BIGINT NOT NULL COMMENT '开单销售员ID',
  `customer_name` VARCHAR(50) NOT NULL COMMENT '客户姓名',
```

### 4 核心字段说明

1. 库存约束：`available_stock = total_stock - occupy_stock`；
2. 乐观锁：inventory.version，每次库存更新 version+1，更新条件带上 version = 当前版本；
3. 数据隔离：所有业务查询SQL强制带上 merchant_id；
4. 状态全部使用数字枚举，前端映射文字展示。

### 5 索引总结

1. 所有业务表建立 merchant_id 普通索引；
2. 订单表：订单号、开单人索引；
3. 库存表：仓库+商品联合唯一索引 uk_warehouse_goods；
4. 列表查询必须带分页、查询条件，避免全表扫描。
